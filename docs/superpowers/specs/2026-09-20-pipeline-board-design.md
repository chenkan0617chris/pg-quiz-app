# 管道题统一可视化设计

## 目标

将管道求解器、管道练习题和答案解析中分散的输入顺序、变换方框和输出顺序，统一为一块接近参考截图的纵向管道画布。画布需要让用户一眼看懂图形从顶部进入、经过每一级 permutation、再从底部输出的过程，同时保留现有求解逻辑、移动端拖拽交换和表单能力。

## 设计原则

- 还原参考图的视觉语言：灰白图形底座、蓝色漏斗、浅蓝连接管、蓝色数字方框和明确的位置编号。
- 保持当前数据模型：本站的 `boxes` 是按顺序执行的多个 permutation，每一级纵向排列，不引入截图中无法由现有引擎表达的并联计算。
- 同一种数据使用同一种视觉组件；求解、练习、答案和动画不再各自绘制一套管道。
- HTML 控件承载拖拽、输入和按钮；SVG 只绘制装饰性连接管，避免可访问性和触摸事件落在 SVG 图形中。
- 移动端优先保证可读性，画布可以纵向增长，但四个图形和四位 permutation 不缩小到难以操作。

## 视觉系统

### 色彩

- `pipe-canvas`：`#F8FBFE`，管道画布背景。
- `shape-tile`：`#EEF1F3`，图形底座。
- `pipe-line`：`#BFE8F8`，半透明连接管。
- `pipe-box`：`#79CDED`，已知 permutation 方框。
- `pipe-deep`：`#1458C7`，漏斗、节点和未知方框。
- `pipe-ink`：`#31566B`，方框数字和辅助标记。

现有绿色、黄色、红色和蓝色图形颜色保持不变。正确答案仍可用绿色状态提示，但管道主体不以绿色作为主色。

### 字体

- 页面正文继续使用项目现有无衬线字体，避免额外字体下载。
- permutation、位置编号和答案使用系统等宽字体，突出它们是位置数据。
- 数据方框使用较松的字间距，但不在四位数字之间加入真实空格，以免复制或提交值发生变化。

### 标志性元素

每块画布都包含“收束漏斗—连接节点—变换方框—展开漏斗”的连续蓝色管道。连接线位于控件背后，视觉上像一个真实的管道系统，但交互目标仍然清晰可点。

## 布局

```text
          1        2        3        4
       [图形]   [图形]   [图形]   [图形]
           ╲      │        │      ╱
                 入口漏斗
                    │
               [ permutation ]
                    │
               [ permutation ]
                    │
                 出口漏斗
           ╱      │        │      ╲
       [图形]   [图形]   [图形]   [图形]
          1        2        3        4
```

- 桌面端画布最大宽度约 520px，居中显示。
- 手机端画布占满容器宽度，图形底座最小 52px，间距随宽度收缩。
- 每增加一个管道方框，画布在中部增加一个纵向 stage，不横向压缩。
- 位置编号是结构信息：输入编号显示在图形上方，输出编号显示在图形下方。

## 组件架构

### `PipelineBoard`

共享的管道画布外壳，负责顶部和底部图形、漏斗、连接管以及多个 stage 的纵向布局。

输入：

- `input`、`output`：四个 shape id。
- `stages`：每一级的显示值、未知状态和强调状态。
- `mode`：`interactive`、`question` 或 `explanation`。
- 可选的输入、输出和 stage 变更回调。

它不计算 permutation，只显示调用方提供的数据。

### `PipelineShapeLane`

显示四个带编号的图形底座。在 interactive 模式复用现有 Pointer Events 拖拽交换行为；question 和 explanation 模式只读。

### `PipelineStage`

显示一个蓝色 permutation 方框：

- 已知值显示四位数字。
- 未知值显示 `????`。
- 求解器 interactive 模式内嵌文本输入、未知复选框和删除按钮。
- 练习 question 模式的未知 stage 内嵌四个单字符答案输入。
- explanation 模式可标记当前步骤和求得的答案。

### `PipelineConnector`

使用 `aria-hidden` SVG 绘制漏斗、节点和连接线。它不接收指针事件，不保存状态。

## 各页面使用方式

### 管道求解器

- 用一块 interactive `PipelineBoard` 替换现有两个 `OrderCard` 和 `BoxesCard` 的三卡片结构。
- 输入、输出继续支持触摸与鼠标拖拽，落点行为保持两个图形直接互换。
- 未知顺序开关放在对应图形行的标题旁。
- 每个 stage 内保留值输入、未知开关和删除操作。
- “添加方框”、候选项与“求解”按钮放在画布下方，不进入管道主体。

### 管道练习

- 题目使用 question `PipelineBoard` 显示输入、已知/未知 stages 和输出。
- 四位答案直接填写在未知 stage 中；移除页面下方重复的四个管道答案输入框。
- 非管道题型维持现状。

### 求解结果与练习解析

- `FlowDiagram` 改为 explanation `PipelineBoard`，展示完整的输入、各级 permutation 和最终输出。
- 练习 `Lesson` 的逐步播放继续保留，但主视觉使用同一画布，通过 active stage 强调当前步骤。
- 候选项、错误提示和文字推导仍在画布外显示。

## 交互与状态

- 拖拽交换沿用已验证的 Pointer Events，实现不改回 HTML Drag and Drop。
- interactive 模式中，标记输入或输出未知后，该图形行降低透明度并禁止拖拽。
- stage 输入只允许 `1`–`4`，最多四位，继续由现有服务端 schema 做最终校验。
- 练习答案输入自动前进到下一格；退格时允许返回上一格。提交仍由现有 form 和 API 完成。
- 删除最后一个 stage 时仍需保留至少一个 stage，避免生成没有管道的求解表单。

## 可访问性

- 图形继续保留本地化 `aria-label`。
- 管道 stage 使用明确的本地化标签，例如“第 2 级管道方框”。
- 未知答案的四个输入分别标注位置 1–4。
- SVG 连接线全部 `aria-hidden` 且 `pointer-events: none`。
- 所有按钮保留可见的键盘焦点；动画尊重 `prefers-reduced-motion`。
- 不使用颜色作为唯一状态表达，未知和当前步骤同时使用文字或边框样式。

## 测试策略

- 先增加组件或端到端回归测试，验证求解器画布包含输入行、stage 和输出行。
- 保留并更新移动端拖拽测试，验证第 1 与第 3 个图形直接交换。
- 增加练习题测试，验证管道答案输入位于未知 stage 内并能提交四位答案。
- 运行现有单元测试、ESLint、TypeScript 和 Next.js production build。
- 本地启动后分别检查中文求解器和管道练习页的桌面、手机视口。

## 非目标

- 不改变 permutation 引擎、题目生成、API payload 或评分规则。
- 不复制截图水印、红色标注线或任何品牌受保护的装饰资源。
- 不改造数字、图形和数据分析题型。
- 本轮只运行本地预览；用户确认视觉效果前不发布生产环境。

## 验收标准

- 求解器中输入、所有 stage 和输出显示在一块连续的纵向管道画布里。
- 练习题使用同一视觉结构，未知 stage 可直接输入答案。
- 求解结果和练习解析使用同一管道视觉组件。
- 手机端四个图形可辨认、可拖拽，交换行为不回归。
- 桌面和手机上连接管不遮挡控件，文字不溢出。
- 所有既有计算、提交和解析流程保持工作。

## 推荐架构与备选

推荐沿用 Next.js，Clerk 管理邮箱登录，Neon Postgres 保存题目、作答及付费权益，Stripe Checkout 收款。托管身份服务负责密码、邮箱验证及恢复密码，避免自行搭建凭据系统。

备选是使用同时提供认证与数据库的服务减少供应商数量；如果收款主体只有中国大陆资质，则另行评估微信支付／支付宝商户接入，不能假定能开通海外 Stripe 商户。

## 登录与访问

- 首页、题型介绍、解题输入界面、练习介绍和套餐页公开。
- 访客点击解题或开始练习时进入登录／注册，完成后回到原站内路径；跳转目标必须限制为安全站内路径。
- 账户提供邮箱验证、退出、找回密码和会员到期时间。
- 所有解题、发题、交卷、历史记录和结算接口分别校验服务端会话；需要会员的接口再校验数据库权益，不能依赖客户端传来的 userId 或会员标记。
- 把解题执行移到服务端；保留格式化工具和类型供客户端使用。接口限制请求大小、题目规模、搜索组合数及调用频率，避免现有枚举算法被过量请求拖垮。

## 收费

建议首版采用一次性购买 30 天使用权，到期手动续费；价格尚未指定，不创建实际收费产品。

- 服务端按内部套餐查找固定价格，创建与登录账户绑定的 Checkout Session。
- 支付成功跳转页只查询订单状态；必须在验证签名的 Stripe webhook 收到已支付事件后开通权益。
- 处理异步支付成功／失败、回调重试、重复事件、退款和争议。Stripe event ID 与 Checkout Session ID 使用唯一约束，订单与权益更新置于事务内。
- 续购在 max(当前时间, 当前到期时间) 基础上延长。退款需按对应订单的权益记录撤销，避免错误清除其他订单购买的时长。
- 金额、币种、套餐、用户归属都在服务端核验。测试与生产密钥、价格及数据库隔离。
- 退款规则、免费体验额度和正式价格需要业务决定；上线前明确展示。

截至审视日期，Stripe 官方文档支持澳大利亚商户接受支付宝和微信支付，两者常规 Checkout 不支持 subscription/setup 模式，循环扣款处于邀请／私有预览阶段。因此首版不依赖自动续费能力。账户能否开通还取决于商户主体、行业和支付方式审核。

## 练习与题库

- 首批覆盖管道推理、数字运算，提供题型及难度选择、逐题提交、正确／错误反馈、解析、下一题和错题复练。
- 管道题先生成合法输入排列和变换序列，再隐藏一个变换；验证答案唯一。
- 数字题先生成符合数字范围和不重复约束的赋值，计算目标，保存题目规则；判分接受所有符合条件的答案，不能只与生成时的一个答案比对。
- 使用现有规则引擎生成原创练习，不声称是官方真题。不依赖 AI 随机出题及不可靠的 AI 判分。
- 每道题保存版本、类型、难度、公开题干、私有答案和解析；发题响应不包含答案。
- 每次练习与用户绑定，服务端计算对错、记录首次提交；重复请求不得重复计分。用户只能读取自己的作答记录。
- 结构化输入继续保留；任意文本／截图自动识别属于另外的解析能力，需要用户提供题目样例明确范围。

## 数据模型

- profiles：身份服务用户 ID、创建时间。
- questions：题型、难度、题目版本、公开题干、答案规则、解析。
- practice_sessions：用户、题目版本、开始及完成时间。
- attempts：练习、用户答案、判分、提交时间；首次计分使用唯一约束。
- orders：用户、套餐、金额、币种、支付状态、Stripe Session／Payment ID。
- payment_events：Stripe 事件 ID、处理状态和处理时间。
- entitlement_grants：订单授予的期限及撤销状态，可追溯退款与续购。
